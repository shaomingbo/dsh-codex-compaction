# Project constraints

- This is an experimental plugin, not a DSH fork. Never edit DSH core or install private-path imports/monkey patches.
- This migration targets only published DSH 0.1.7-alpha.1; retain pi-ai 0.84.4 as the synthetic cross-version owner fixture. Separate tested library composition from live GUI verification.
- Do not touch the running DSH process, real profiles, settings, credentials or sessions in tests. Use temporary storage and injected fake transport/auth.
- No staging, commits, tag creation, GitHub publication, catalog approval or live installation without explicit authorization.
- Run `npm run check`, `npm pack --dry-run --ignore-scripts`, `git diff --check` before claiming local completion. Existing tests are Node.js node:test, no lifecycle install scripts.
- Preserve upstream license notices when copying code. Native protocol references are documented; new code is independently implemented.
- The approved 2026-09-23 direction is a BasicCompactionEngine subclass overriding ONLY summarize(input, agent, signal). Basic owns all triggers, selection, pruning, transactions and metering. Native runs through the account-owned codex-runtime/v1 lease and returns an unmarked SummaryResult (no llmStreamCall:true); non-native summaries use super.summarize. The declarative codex-native-b preset mirrors standard. Per-session /codex-native defaults off, recovered through public async command events. At most one transparent text fallback stays on the same owner lease/account, with no native retry. Middleware and Structured B are readers only. Unknown identity/protocol, cancellation and malformed replay fail closed. Never fabricate usage.
- Explicit `/codex-native reader-text` may ask that same owner reader for a text summary with Basic's complete instruction; Basic alone validates and commits it. This is not native-failure fallback, does not change defaults, and must not be automatically selected before separate quality acceptance. Benefit diagnostics are bounded metadata-only observations, never token-meter or history overrides.
- Authentication, native HTTP, codec and model catalog belong to the existing account owner's codex-runtime/v1 Module. Production compaction code must not import a native SDK, create a credential store/login flow or receive OAuth values.
- The account workspace's node_modules may link to the live Web profile. Never install dependencies there; use scripts/account-snapshot.js and the explicit isolated paired-checkout suite.
- The candidate GitHub repository/tag in metadata is NOT an existing published artifact; catalog candidate must remain blocked until real release identity and human approval exist.
